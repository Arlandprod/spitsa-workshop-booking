# Спица — демо записи в веломастерскую

Самостоятельный учебный/портфолио MVP. Вымышленная русская веломастерская, один мастер и один рабочий пост. Посетитель выбирает услугу, дату и время, получает подтверждение, переносит или отменяет запись. Владелец в открытом демо-кабинете видит записи и меняет часы отдельного дня.

**Это локальное браузерное демо, не система записи реального бизнеса и не production-ready сервис.** У каждого браузера своя IndexedDB. Данные не общие между устройствами или посетителями. Демо-вход не проверяет личность и не защищает данные; все действия доступны каждому в его локальной копии. Только вымышленные данные, без телефона и email. SMS, email, платежей, аналитики и внешних API нет.

## Установка и запуск

Рекомендуется **Node.js 24 LTS** и npm. Зависимости фиксированы в `package-lock.json`.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite (обычно `http://127.0.0.1:5173`). `.env` не требуется; `.env.example` объясняет отсутствие секретов. Открывать `index.html` через `file://` нельзя: нужен HTTP-сервер.

```sh
npm run typecheck
npm test
npm run build
npm run preview
```

`build` создаёт самостоятельную оптимизированную сборку **`dist/`**. Ей не нужен Node на сервере, Sites, Vercel или аккаунт ChatGPT. `preview` подходит для локальной проверки, а на VPS статические файлы обслуживает Nginx/Caddy. Шрифт Manrope и иконки включены в сборку; запросов к Google Fonts/CDN нет.

## Сценарии

1. В «Записаться» выбрать одну из четырёх услуг, дату и время. Ввести вымышленное имя, при желании описать учебный велосипед, отметить использование демо-данных. «Подтвердить запись» сохраняет запись и показывает подтверждение.
2. «Мои записи» → «Перенести» → выбрать новый интервал → «Подтвердить перенос». Старый интервал освобождается только после успешного сохранения нового; при конфликте исходная запись остаётся.
3. «Отменить запись» запрашивает подтверждение. Отмена освобождает интервал и сохраняется в истории; обратного восстановления отменённой записи нет, можно создать новую.
4. «Владельцу» → «Войти в демо-кабинет». Выбрать день, посмотреть записи, перенести/отменить визит, изменить часы или объявить день выходным. Перекрыть подтверждённую запись изменением часов нельзя.
5. Во второй вкладке того же адреса попробовать занять тот же интервал. База сериализует запись: подтверждение получает только один запрос. Вкладки обновляются через BroadcastChannel, при фокусе и раз в 30 секунд.
6. «Сбросить демо-данные» в кабинете с подтверждением очищает **только базу этого приложения**: ваши записи и особые часы заменяются тремя синтетическими примерами. Seed создаётся относительно текущей московской даты и не дублируется при перезагрузке.

## Правила времени

- Мастерская работает по **Europe/Moscow (UTC+3)** независимо от часового пояса устройства. Для современного горизонта бронирования московское время имеет фиксированное смещение; произвольные исторические даты/DST иных зон не поддерживаются.
- Вт–Сб 10:00–19:00, перерыв 14:00–15:00; Вс 11:00–16:00 без перерыва; Пн выходной. Кабинет позволяет переопределить конкретный день.
- Шаг начала — 30 минут, услуги — 30/60/90 минут. Проверяется весь интервал, включая закрытие и перерыв. Соседние визиты допускаются: конец предыдущего равен началу следующего.
- Доступны сегодня и следующие 21 календарный день, минимум за 60 минут до начала. Перенос подчиняется тем же правилам. Отмена — до начала. Прошедшие записи становятся неизменяемой историей.
- Доверяем часам браузера. Для настоящего сервиса нужны серверные часы и серверные проверки.

## Архитектура

Простой React + TypeScript + Vite, Tailwind CSS 4. Без backend и без скрытого облачного хранилища.

| Файл | Ответственность |
| --- | --- |
| `src/domain.ts` | Услуги, время, доступность, валидация, seed и правила расписания |
| `src/db.ts` | IndexedDB, атомарные изменения, версии записей, уведомления вкладок |
| `src/App.tsx` | Три представления, обновление локального состояния и подтверждение |
| `src/components/` | Форма, список записей, кабинет и диалоги подтверждения |
| `src/webmcp.ts` | Необязательные браузерные tools; без них весь UI работает |
| `src/styles.css` | Палитра, компоненты, адаптивность, клавиатурный фокус |

В IndexedDB `spitsa-workshop-demo-v1` хранится один документ `workshop` в store `state`: записи, особые часы, ID созданных посетителем записей и ревизия. **Чтение → проверка → изменение выполняются внутри одной `readwrite`-транзакции с общим store scope.** Это предотвращает двойное бронирование при одновременных запросах и в разных вкладках одного origin. Проверка доступности перед submit нужна для UI; окончательное решение принимает транзакция. Перенос и изменение расписания используют тот же механизм. Версия отдельной записи защищает от устаревшей отмены/переноса.

Демо-вход и `mineIds` — элементы интерфейса, а не авторизация. Сам посетитель контролирует браузерную базу и может её редактировать. Для реального многопользовательского сервиса эту границу нужно заменить backend, общей БД, транзакциями, настоящей авторизацией и политикой обработки данных.

## Тесты

```sh
npm test
npx playwright install chromium
npm run build
npm run test:e2e
```

Vitest + fake-indexeddb проверяют московскую дату, високосные/несуществующие даты, рабочие часы и длительность, частичные пересечения, валидацию, гонку восьми записей, перенос/rollback, отмену, устаревшие версии, конкуренцию с закрытием дня и безопасный reset.

Playwright проверяет готовую сборку `dist`: создание → перезагрузку → перенос → отмену, две вкладки, кабинет и запрет закрытия занятого дня, перенос синтетического визита владельцем, мобильную ширину 390px, пустые состояния, ввод HTML как текста. Часовой пояс тестового браузера намеренно отличается от мастерской. Тесты работают с фиксированными часами и своей браузерной базой.

WebMCP — необязательная развивающаяся браузерная возможность. Проверяются регистрация, схемы и реальные транзакции через тестовую реализацию API; штатная поддержка конкретным браузером не гарантируется. В GitHub Actions те же проверки выполняются на Node 24 и Chromium. Фактические результаты текущего релиза указаны в `docs/VALIDATION.md`.

## Свой VPS и поддомен

Сервер/домен в рамках проекта не куплены, DNS/TLS не менялись, VPS-деплой не выполнялся. Подходит один VPS для нескольких демо: это приложение размещается на своём поддомене, например `spitsa.example.com`. VPS-версия открывается обычным браузером без входа в ChatGPT. Доступность из РФ зависит от выбранного вами хостинга и сети; она здесь не проверялась.

### Статические файлы

На машине сборки выполнить `npm ci && npm run build`, затем скопировать **содержимое** `dist/` в `/srv/www/spitsa/` на собственном сервере. Адаптировать `deploy/nginx-subdomain.conf`: заменить пример домена и путь, подключить к своему Nginx, проверить `nginx -t`, затем перезагрузить конфигурацию. HTTPS настраивается вашим обычным способом. Используйте отдельный root и vhost; конфигурация существующих сайтов не должна заменяться.

Сборка рассчитана на корень отдельного поддомена. Для размещения в подпапке нужны изменение Vite `base` и URL favicon; это не готовый режим v1.

### Docker-вариант

```sh
docker build -t spitsa-demo:1 .
docker run --rm --name spitsa-demo -p 127.0.0.1:8092:80 spitsa-demo:1
```

Проверить `http://127.0.0.1:8092`, затем направить собственный reverse proxy поддомена на этот порт. Dockerfile собирает из lockfile и раздаёт `dist` через Nginx. Контейнер не хранит записи: persistence и reset остаются **в браузере посетителя**, поэтому volume БД не требуется. Образы Docker используют версии/tags; для полностью фиксированной инфраструктурной сборки можно самостоятельно закрепить их digest. Docker/VPS-конфигурация подготовлена как инструкция и не означает, что реальный сервер уже запущен.

## Ограничения v1

- Локальная persistence: разные браузеры, профили, origins и устройства имеют независимые данные. Очистка данных сайта/инкогнито может их удалить. При изменении домена автоматического переноса нет.
- Нет backend, общей очереди клиентов, настоящего входа, роли/прав доступа, резервных копий и контактных данных. Демонстрационный кабинет публично доступен в UI.
- Одно рабочее место; нет нескольких мастеров, выходных по праздникам, повторяющихся исключений, оплаты, уведомлений и учёта запчастей.
- Услуги/цены/стандартная неделя заданы в коде, меняются в `domain.ts`. Кабинет изменяет отдельные дни в пределах горизонта.
- Нет offline service worker: после загрузки бизнес-операции локальные, но первоначальный запуск требует доступной страницы.
- Автоматическая проверка браузера — Chromium; Safari/Firefox вручную не проверены.
